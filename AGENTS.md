# Agent Development Notes

This is a Foldkit app. Read [`FOLDKIT.md`](./FOLDKIT.md) before writing any code in this project. It covers the architecture, the APIs, and the conventions the project is built on.

A root uses one of two complete layouts. A genuinely compact root keeps Model, Message, init, update, view, `ApplicationDefinition`, `ApplicationComposition`, `ApplicationBlock`, and any small local handler bundle together in `application.ts`. Once any root responsibility is extracted, split the whole root: retain `definition.ts` for `ApplicationDefinition` when authoring methods use it, or put a top-level `Block.makeDefinition('Application', ...).makeComposition()` chain in `composition.ts` when they do not; `model.ts`, `message.ts`, `init.ts`, `update.ts`, `view.ts`, and optional `flags.ts` own their named responsibilities; `composition.ts` owns Bindings, OutMessage folds, complete child/Mount registration, `ApplicationComposition`, and an optional `ApplicationViewBuilder`; and `block.ts` assembles `ApplicationBlock`. Even a graphless split root has `composition.ts`. Remove the emptied `application.ts` instead of using it as a forwarding barrel. A simple root `EffectsLayer` stays with its Command definitions in `command.ts`; use `layer.ts` only for substantial or reused Layer composition. Composition imports the Definition and child or Mount definitions, never root init, update, or view. Create every root with `Block.makeDefinition('Application', { Model, Message })`, author init, update, and the primary view through its Composition, then pass them explicitly to `ApplicationComposition.prepareBlock(...)` inside the private `prepare` producer. Put the adjacent `ApplicationBlock: Block.FromAssemblyWithView<typeof Model, typeof prepare> = Block.assemble(prepare)` export on the next line with no blank line. A split feature uses composition.ts, including for Mount-only registrations. Shared Mount definitions live in mount.ts. Parent-owned Bindings from `ApplicationDefinition.makeBinding(...)` are passive relationship configuration; including them in the Composition's `bindings` registers them. `entry.ts` imports `ApplicationBlock`, owns the browser container and startup inputs, creates the host with `Program.make` or `Program.makeElement`, calls `program.provide(ApplicationLayer)` when needed, and starts the Runtime. Keep root `ApplicationLayer` composition in `services.ts`. Tests and server entries import the passive Block without starting the browser Runtime. Name the root Route union `ApplicationRoute` and the root provider `ApplicationLayer` (`ApplicationTestLayer` for its test alternative).

## Project Notes

The Foldkit application root is `src/client/`, including `entry.server.ts`: server-side UI rendering belongs to the frontend application. `src/server/entry.ts` is the Worker entry; it re-exports the rendering hooks, dispatches RPC requests, and exports Durable Object classes. Backend services live in `src/server/`; domain contracts, RPC contracts, and the candidate catalog live in `src/shared/`. Client code and backend services may import shared contracts. Shared code must not import client or server implementations. Backend services must not import client code; the Worker entry is the SSR bridge. Command and backend execution tests may connect the real client and server transports.

All root update Stories live under `src/client/story/`: `application.story.test.ts`, `progressiveQuotes.story.test.ts`, `cachedQuotes.story.test.ts`, and `cooldown.story.test.ts`. The filenames group application behaviors; every Story drives the root update. View interactions live in `src/client/scene.test.ts`. Share repeated URL handoffs and quote completions through `src/client/story/test.ts`; keep race-sensitive delivery ordering visible in each Story. Name tests for the trigger and observable result, and give parameterized cases distinct diagnostic names. Prefer role, label, and text locators in Scenes; use selectors for presentation structure or explicit attribute wiring. Use Scene routing configuration and explicit `Navigation.changedUrl` for typing through URL replacement, routing delivery, Clock admission, fetch completion, and displayed results. Navigation Command completion and routing delivery are separate causes. Prefer Effect `Array`, `String`, `Option`, and other data modules throughout application logic. Match literal unions exhaustively with `Match` and tagged unions with their own matcher.

Name values and operations for the exact domain entity and cardinality they represent. A quote window is one offset/limit range; a cached quote window stores that range's response; a listing may be pending or contain a checked Domain. Include units in numeric deadline and geometry names.

Export a same-named decoded type beside app-owned Schemas (`export type Domain = typeof Domain.Type`) and use that name in annotations. Keep qualified variant types such as `typeof Domain.Available.Type` and child-owned types such as `typeof ResultsListBlock.Model.Type` when their precision or ownership is useful.

Export the used Step helpers from `definition.ts` and import them by name in `update.ts` and composition policies. Export the used Definition authoring helpers alongside the Step helpers; qualify through `ApplicationDefinition` when a module works with multiple Definitions and the qualifier identifies the owner. Use `makeFieldsStep` for field-only handlers and `makeCommandsStep` for Command-only handlers; use `.fromMessage` when the producer needs only the payload. Reuse `makeStep` for mixed state-and-Command transitions, compose sequential Steps with `Update.combineSteps([...])`, and put reusable startup transitions in init's `steps` plan.

Name reusable Step values `<operation>Step` and factories that return Steps `make<Operation>Step`, such as `searchQueryStep`, `clearSearchStep`, and `makeChangeSearchQueryStep`.

Reusable parent-owned Steps shared by update, composition, or init live in `steps.ts`. When they need subdivision, use responsibility-named files under `steps/` with an explicit `index.ts` barrel. Update maps Messages to Steps; composition registers relationships and maps child OutMessages to parent Steps. Composition imports the leaf Step module it uses. Keep Binding reads inside deferred producers when shared Step modules and composition depend on one another. Keep named domain types visible in useful annotations, including intermediate collections whose inferred hover expands their domain structure.

`quoteWindows.ts` owns the canonical KeyedQuery Block for `{ label, offset, limit }`. Use its bound public operations; never modify its Model internals. The root owns `quotePlan`, the windows selected for the active Route, and `searchGeneration` only for delayed planning Clock admission. `searchPresentation.ts` projects status and merged quotes from Query data for the view. Its Schemas describe derived presentation, not another canonical fetch state. Viewport selection plans one window at a time. A failed later window waits for explicit retry, and accepted Query completion OutMessages coordinate the next window.

Follow the pinned `query-sync` example for Route-backed state: input Messages request URL replacement; changed queries immediately invalidate and cancel pending lookups; `ChangedUrl` parses and stores the Route before starting its lookup. Keep unknown paths as `NotFound` through view and server response handling. Navigation uses separate `NavigateInternal` and `LoadExternal` Commands. Use the shared `cancelSearchStep` to cancel pending Query windows through their Binding.

Styling follows the Foldkit website: Tailwind Vite integration, a local theme, base styles, component classes built with `@apply`, and layout utilities in view. Restrict Tailwind source detection to `src/client` so the vendored framework does not contribute utilities. Preserve the direct development stylesheet link before hydration.

The `domains:refresh-ssr-definitions` Vite plugin invalidates the SSR module graph before live reload. The pinned preview otherwise retains Block Definitions while recreating Commands and rejects duplicate registration.

Availability and registration/renewal quotes are live registrar data from the same-origin Effect backend. The cart is a demo. Keep test quotes in fixtures and never fall back to invented prices or availability. A registrar result that is unavailable or unconfirmed has no quote. Keep domain names derived from the current query, and hide prices, availability, and cart actions until that query's lookup completes. Preserve the single input node and pre-hydration edits when changing search layout or startup.

`bootstrap.ts` is a native browser boundary that runs before Foldkit starts. Its listeners end at the `domains:ready` handoff. After hydration, Model, Messages, and Commands own the search. Keep `ReplaceSearchUrl` written with `Effect.gen`.

Use `pnpm test:e2e` for the production hydration checks. Its server port is 5180. `pnpm test:e2e:dev` checks stylesheet delivery before client scripts run on port 5181. Neither suite may reuse an existing server. The static deployment output is `dist/client`.

For a required direct child field, omit `init` when its initializer accepts no arguments; use `init: { contextToArgs }` for required inputs or `init: false` when the parent supplies that field. Optional, keyed, and accessor storage remains parent-owned when `init` is omitted; explicit `init.contextToArgs`, keyed `init.instances` / `init.toItem`, or a checked custom projection chooses automatic startup. An optional `ChildInitContext` Schema on the parent Definition contextually types selectors that prepare arguments for direct child initializers. Author root startup through `ApplicationComposition.makeInit`, returning parent-owned `model` fields plus optional ephemeral `childInitContext`, parent `commands`, and post-assembly `steps`. Composition initializes and places child Models and collects their Commands. Use an exhaustive `ApplicationComposition.makeUpdate` handler record for parent transitions; registered Bindings route generated child envelopes before local handlers. Put delivery admission in `delivery.when`, derive required child update context with `delivery.toUpdateContext`, and provide `keySchema` for a custom keyed Binding. See FOLDKIT.md for optional presence, exact keyed identity and startup Steps.

Deployment lives in `infra/alchemy.run.ts` and uses the pinned Alchemy Cloudflare Foldkit resource. Keep infrastructure dependencies in `infra` so its Effect version can follow Alchemy while the app satisfies the Foldkit preview’s exact peers. Typecheck both workspaces. `wrangler.jsonc` supplies the local workerd check on port 5182; Alchemy owns deployment. Run `pnpm test:e2e:worker` for Workers routing and browser integration, and `DOMAINS_BASE_URL=<preview-url> pnpm test:e2e:preview` against a deployed preview. Keep credentials and generated `.alchemy` / `.wrangler` directories out of Git.

Domain search uses the shared `DomainsRpcs` contract over HTTP at `/rpc`, returned through `Server.Responded` in `src/server/entry.ts`. `DomainsClientLayer` lives for the browser Runtime, and `QuoteWindows` captures its client in the Query handler generator. Preserve typed `SearchError` failures and let interruption abort the request without producing a failure Message. `pnpm preview` runs workerd so RPC and assets are served together. Execute production Command and backend Layers with controlled external services in execution tests; keep Story/Scene tests for Model and view invariants. Browser regressions use the shared RPC server with fixture handlers so CI does not depend on registrar data or uptime. Ordinary Workers cannot await pending I/O owned by another HTTP request. Production shared lookups belong to the per-label DomainSearchCoordinator Durable Object; the RegistrarCoordinator Durable Object owns provider admission and cooldown across labels. The Cloudflare classes are host adapters around object-scoped ManagedRuntimes. `DomainSearch` owns cache storage and shared lookup fibers; waiter acquisition and release use an Effect resource bracket so one caller cannot cancel another. Its mutable pending-search map holds opaque Fiber handles, not serializable app data. `RegistrarSearch` owns Refs for quotas and client windows, bounded queue membership, scoped semaphore permits, and Effect Clock deadlines. Native binding types stay at the Cloudflare boundary; backend consumers use `CoordinatedSearchClient`. Preserve existing Durable Object class names, binding names, migrations, and stored budget/cache formats. The in-process development backend caches completed quotes only. Scope the RPC server transport to its HTTP request; avoid shared request-lifetime permits that depend on cleanup after the host cancels an invocation. The worker suite runs a production-Layer RPC fixture with a controlled provider on port 5183 to protect this boundary. The pinned preview needs a shared `development` build identity in Vite for coordinated client/SSR hydration.

Debounce uncached live lookups for 350 ms while input and pending names update immediately. The root Model owns `quoteWindows`, a Schema-backed KeyedQuery with fixed one-minute freshness and `maxSettledEntries: 100`. A Clock Command reports the time through `CompletedDetermineSearchTime`; pure Steps pass that timestamp to `requestLoadIfStale`. Fresh hits touch recency without renewing completion-based freshness and bypass debounce, RPC, and provider cooldown. Stale data stays retained; pending quotes and cart actions are hidden, and a failed refresh may retain previous quotes. The Query bounds settled successes and failures; pending windows are protected. Its generations reject stale, canceled, and duplicate completions. Accepted completion OutMessages drive parent window planning. Do not add a second cache, copied success collection, or cache-expiry Subscription.

Keep `maybeSearchCooldown` in the parent Model. Before admitting uncached work or a forced refresh, check the latest planning Clock time against its deadline; fresh cache access remains usable. Install rate limits only through an accepted completion for the current search. A Subscription removes expired cooldowns, and a local block preserves the original deadline. Keep credentials and mutable cooldown state out of the Query handler constructor. Persist provider admission windows and cooldown deadlines on the backend. A label coalesces pending windows inside its Durable Object; every client owns a waiter, and only the final cancellation aborts the shared lookup. Keep Cloudflare's request cancellation flags enabled.

Quote loading is progressive: the first request covers 60 candidates, scrolling requests missing pages from the visible and overscan window, and global price sorting or availability filtering requests the complete catalog. Derive a later-page failure alongside retained checked quotes so they stay usable. Include offset and limit in cache identity. Production caches are shared per label and the registrar budget is shared across all labels. `REGISTRAR_REQUESTS_PER_SECOND`, `REGISTRAR_REQUESTS_PER_MINUTE`, and `REGISTRAR_MAX_CONCURRENT` must reflect the provider’s confirmed allowance; defaults do not establish live provider capacity. Run `pnpm test:capacity` for native coalescing, load, cancellation, cache, and quota regressions against a controlled provider. The local HTTP adapter does not forward disconnect signals, so the native cancellation fixture injects a Request abort at the Worker boundary.

VirtualList uses `ScrollContainer.Window()` with `rowLayout: 'Absolute'`. Keep the document as the single vertical scroll surface beneath the sticky navigation. Its Model `scrollTop` is the signed offset from the list’s origin, so quote loading uses it directly with the measured page viewport. Preserve visible-row anchoring across responsive layouts, and keep later-page retry feedback reachable without scrolling to the catalog’s end. Arrow keys, Page Up, Page Down, and Home use the instant `ScrollPage` Command. End uses the bound VirtualList `requestScrollToEnd` operation so the final virtual row is rendered and measured before its scroll completes.

The responsive results grid uses CSS container breakpoints at 668px and 944px. `estimateDomainListingGroupHeightPx` supplies matching VirtualList estimates and progressive quote-planning geometry; dynamic measurements handle wrapped names and prices. The pinned UI package uses a tracked pnpm patch to order changed-width measurements before scroll observations, preserving the pre-reflow anchor across responsive layouts. Preserve the exact browser resize-anchor assertion when upgrading the dependency.
